# APPVERSE 운영 가이드

`index.html` 하나로 동작하는 웹앱 체험 플랫폼입니다. 현재 버전은 **정적·로컬 모드**이며 서버에 연결되어 있지 않습니다.

## 1. GitHub Pages 배포

1. GitHub에 공개 저장소를 만들고 `index.html`을 저장소 최상위에 올립니다.
2. Settings → Pages → Build and deployment에서 Deploy from a branch를 고르고 `main` / `(root)`로 저장합니다.
3. `https://사용자명.github.io/저장소명/`으로 접속합니다.

해시 라우팅(`#/app/ID`)을 쓰므로 404 설정 없이 상세 페이지 직접 링크가 동작하고, 하위 경로에서도 그대로 실행됩니다.

iPhone Code·Koder 앱에서는 `index.html`을 열면 실행됩니다. 앱의 웹뷰 설정에 따라 저장소나 파일 선택이 제한될 수 있습니다.

## 2. 관리자 데모 사용

1. 왼쪽 위 APPVERSE 로고를 연속으로 10번 누릅니다(입력 간격 0.9초 이내).
2. 아이디 `admin`, 비밀번호 `1234567890`으로 로그인합니다.
3. 로그인 중에는 전체 메뉴에 관리 센터가 나타나고, 15분 동안 사용하지 않으면 세션이 만료됩니다.

**이 계정은 보안 수단이 아닙니다.** 공개 코드에 그대로 들어 있어 누구나 볼 수 있습니다. 대신 이 화면에서 바꾼 내용은 그 사람의 브라우저에만 저장되므로, 공개 목록에는 영향을 주지 못합니다.

## 3. 웹앱 등록

**URL 등록**: 관리 센터 → 등록 센터 → URL 등록. `https://` 주소 또는 같은 저장소의 `apps/폴더/` 상대경로를 입력합니다. `http://`는 localhost와 사설망 주소만 허용하며 `javascript:`, `data:` 등은 차단합니다.

**ZIP 가져오기**: 등록 센터 → ZIP 가져오기에서 파일을 고르면 내부 구조, 경로, 확장자, 크기를 검사하고 `index.html`을 찾습니다. 실행 테스트로 격리 환경에서 돌려 본 뒤 저장합니다. ZIP은 **이 브라우저의 IndexedDB에만** 저장되며 다른 방문자에게는 보이지 않습니다.

**ZIP을 공개하려면** 저장소에 압축을 풀어 올린 뒤(예: `apps/my-app/index.html`) 해당 웹앱의 "공개 배포 경로"에 `apps/my-app/`을 입력하고 아래 공개 목록 갱신을 진행합니다.

## 4. 공개 목록 갱신

1. 관리 센터 → 데이터 → **공개용 apps.json 만들기**를 누릅니다.
2. 받은 `apps.json`을 `index.html`과 같은 폴더에 커밋합니다.
3. 잠시 후 모든 방문자가 새로고침하면 반영됩니다.

공개 배포 경로가 없는 ZIP 앱은 자동으로 제외됩니다. `apps.json`이 없으면 `index.html` 안의 `appverse-seed` JSON을 사용합니다. 등록 데이터가 적고 파일 하나만 유지하려면 `apps.json` 내용을 이 블록에 붙여도 됩니다.

저장소에 쓰기 권한이 있는 사람만 공개 목록을 바꿀 수 있으므로, 이 방식에서는 GitHub 계정 권한이 실제 관리자 보호 역할을 합니다.

## 5. 구현된 기능

- 홈: 추천, 공지, 즐겨찾기, 최근 등록, 카테고리, 최근 업데이트, 전체 목록, 빈 화면 안내
- 탐색: 실시간 검색, 카테고리 필터와 개수, 정렬, 카드/리스트 전환, 상태 유지, 지연 렌더링
- 상세: 커버, 아이콘, 주요 기능, 스크린샷, 변경 내역, 실행 방식 선택, 즐겨찾기, 공유, 링크 복사
- 실행: iframe 실행, 새로고침, 전체화면(미지원 시 대체 UI), 새 탭 열기, 실패 안내, 종료 시 복원
- ZIP: 자체 파서, 경로 이탈·심볼릭 링크·암호·용량 검사, 상대경로·ES Module·fetch 연결, sandbox 격리 실행, 내부 페이지 이동
- 관리자: 대시보드, 등록·수정·삭제와 실행 취소, 다중 선택 일괄 작업, 순서 변경, 버전 기록, 카테고리, 공지, 홈 구성, 설정
- 데이터: 전체 JSON과 ZIP 원본 백업, 검증과 복원 전 미리보기, 충돌 처리, 복원 취소, 브라우저 내 백업, ZIP 기록
- 모바일: 내부 스크롤 구조로 고정된 하단 메뉴, Safe Area, 더블탭 확대 방지, 입력창 16px, 브라우저 뒤로가기 연동
- 기타: 라이트/다크/시스템 테마, 키보드 탐색, 모션 줄이기, 생성형 기본 썸네일, 스켈레톤, 토스트

## 6. 제약사항과 미구현

| 항목 | 내용 |
|---|---|
| 공개 쓰기 | 서버가 없어 관리자 화면에서 바로 전 방문자에게 반영할 수 없습니다. apps.json 커밋이 필요합니다. |
| iframe 차단 감지 | 브라우저가 교차 출처 차단 여부를 알려 주지 않아 자동 판별할 수 없습니다. 실행 화면 하단에 새 탭 열기를 항상 표시합니다. |
| 외부 브라우저 열기 | 웹 페이지는 특정 브라우저를 지정할 수 없어 새 창 요청으로 동작합니다. 실제 위치는 앱과 OS가 결정합니다. |
| 인기순 | 조회수를 수집하지 않아 숨겨져 있습니다. 서버가 `launchCount`를 제공하면 나타납니다. |
| ZIP 미리보기 | Service Worker, 일부 동적 import, 절대 URL 의존 앱은 실패할 수 있습니다. ZIP64와 암호 ZIP은 지원하지 않습니다. |
| ZIP 새 탭 실행 | 플랫폼 저장소가 노출되므로 일부러 막았습니다. 격리 iframe으로만 실행합니다. |
| 같은 도메인의 앱 | 내부 실행 시 저장소 접근을 막아 일부 앱이 동작하지 않을 수 있습니다. 새 탭으로 열면 같은 출처가 되므로 신뢰하는 앱만 등록하세요. 앱별 도메인 분리를 권장합니다. |
| 핀치 확대 | 접근성을 위해 유지합니다. 더블탭 확대만 막습니다. |
| 로컬 데이터 | 브라우저 데이터를 지우면 사라집니다. iOS는 오래 쓰지 않은 사이트 저장소를 지울 수 있으니 JSON 백업을 받아 두세요. |

## 7. 서버 연동 확장

화면은 `Repo`만 호출하고 저장은 `Backend` 객체가 담당합니다. 스크립트의 `RemoteBackend`를 구현하고 `CONFIG.MODE`를 `'remote'`로 바꿉니다.

- `loadPublished()`: 공개 목록 조회
- `loadOverlay()` / `saveOverlay()`: 서버 모드에서는 앱·공지 API 호출로 대체
- `Auth`: `CONFIG.DEMO_ACCOUNT`를 제거하고 Supabase Auth, Firebase Auth 등 서버 검증 세션으로 교체
- ZIP: Storage 대신 앱별 고유 도메인에 배포 (플랫폼과 같은 출처로 서빙 금지)

권한은 브라우저가 아니라 데이터베이스에서 강제해야 합니다. Supabase 예시:

```sql
alter table apps enable row level security;
create policy "public read" on apps for select using (is_published);
create policy "admin write" on apps for all
  using (exists (select 1 from admins where user_id = auth.uid()))
  with check (exists (select 1 from admins where user_id = auth.uid()));
```

공개 코드에는 anon key만 넣고 service_role 키와 관리자 비밀번호는 절대 넣지 않습니다. 시나리오 21(관리자 쓰기 API 우회 불가)은 이 단계에서 서버 측으로 검증해야 합니다.
